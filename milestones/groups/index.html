Published Groups on VulNyx

Medium-difficulty Alpine Linux target built for VulNyx.

Most boxes ask you to find a missing input check or a forgotten password. With Groups, I wanted to build something around application availability and a maintenance shortcut gone wrong. The machine simulates an internal log console called logiscope running on a minimal Alpine host.

Built and tested on VirtualBox, this VM invites you to explore the service blind before looking at how the watchdog and system groups interact.

How was this machine built and solved? Contains spoilers

I built logiscope as a single-process Werkzeug server on a one-vCPU Alpine VM where an admin form accepts custom regex rules. Because a backtracking pattern locks Python's global interpreter lock on every event, even the separate health probe hangs when the server gets flooded.

Around that bottleneck, I added a minute-by-minute cron watchdog that fails open after two missed health checks by opening a recovery netcat listener on port 8090 as a setup user. Putting that account in the disk group lets players read and write the raw root partition directly, patching Alpine's privilege config past normal file permissions.
